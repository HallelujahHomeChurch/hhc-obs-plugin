# Actual Windows NVENC session exhaustion

The developer check `tests/nvenc-exhaustion-test.ps1` ran against isolated portable OBS32.2.2, RTX4060 and driver617.14. It uses the existing local developer fixture compiled from candidate source f009725, with no production plugin, OAuth, HTTP or YouTube start intent. Test/source evidence commit is06f63d7. No product code or encoder configuration changed.

The test refuses an existing NVENC workload or an active owned OBS instance, then opens low-frame-rate synthetic FFmpeg NVENC sessions. On this actual machine,12 sessions opened and the next request failed. With all12 held, OBS's real module probe reported `session_limit`, disabled NVENC and did not register obs_nvenc_h264_tex. HHC rejected startup, OBS exited0, and its retained local journal had zero objects, normalEnd=false, stopIntent=false, sealAcknowledged=false and confirmedReady=false. No m4s media or x264 encoder initialization event appeared.

After releasing exactly two owned holders, the module probe succeeded. HHC1080p and720p NVENC settings initialized; the remaining encoder initialization failed with code21, `NV_ENC_ERR_INCOMPATIBLE_CLIENT_KEY`. OBS exited0, the second journal retained the same incomplete/zero-object state, and GPU session count returned to the10 surviving holders. This measures partial-initialization resource cleanup as well as startup rejection. It does not prove physical GPU removal or an encoding-time device failure.

Only test-owned FFmpeg processes are terminated during cleanup; an OBS observation timeout is preserved rather than forcing a restart. All holders were released and measured GPU encoder session count returned to0. A separate actual five-second local capture then completed with OBS exit0: one fragment/rendition,5.005 seconds,30000/1001fps, three H.264/AAC formats, hashes, sizes, aligned timelines and full decoding passed. Both failed-start journals remained byte-identical after that independent successful capture. This is not same-dock operator retry or platform E2E acceptance.

Two setup failures are preserved separately. Initial128x128 holder input was below the driver's minimum dimensions and established no session; it is not plugin failure evidence. The640x360 attempt actually reached session exhaustion, but the initial QA assertion expected an encoder-level out-of-memory status instead of the earlier module-probe session_limit path. The corrected runnable check verifies the observed module path and the separate encoder-initialization path. Final result is exit0, with logs and media under `artifacts/nvenc-exhaustion-partial-06f63d7`; adjacent JSON contains safe receipts and hashes.

Original installed OBS profile/recording/stream encoder hashes remain unchanged. These developer runs report one allocation at exit; cause and leak-free operation remain unqualified. Candidate package f009725 is unchanged and unsigned. Live recovery, current positive seal/ready/publication/member playback and production long-run acceptance remain separate gates.
