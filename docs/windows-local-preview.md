# HHC OBS Windows x64 K3 候選版

適用 OBS 32.2.2 x64／Qt 6.11.1。本包尚未簽章，K3 真 OBS 與正式平台驗收尚未完成。本機、CI、上傳完成、平台 ready 與發布是不同結果。

## 安裝

關閉 OBS，解壓縮候選包，將 `obs-plugins` 與 `data` 資料夾複製到 OBS 安裝資料夾並保留目錄結構。背景補傳程式與 Schannel TLS 元件必須一起安裝；不要替換 OBS 的 Qt 或 FFmpeg DLL。操作人員不需要 CLI。

開啟 OBS，在「停駐視窗」啟用 **HHC 影音**。先確認 Program 為 1920×1080、30000/1001 fps、NV12、BT.709／有限範圍，音訊為 48 kHz 雙聲道。外掛不修改原設定；NVENC 失敗不切換 CPU。

## 一次儲存金鑰，每場開始／停止傳送

1. 在 HHC Console 取得串流金鑰，貼到外掛並按 **儲存串流金鑰**。金鑰與場次 session 僅存於 Windows Credential Manager；新流程不需在外掛登入。
2. 在 Console 設定標題、縮圖、時間及直播／發布選項，準備本場直播。外掛不選場、不編輯這些資料，只顯示平台回傳的標題。
3. 選擇音軌 1–6，確認來源有送到該音軌，再按 **開始 HHC 傳送**。尚未準備場次會等待；此時可按停止取消等待。
4. Console 控制公開開始與結束。外掛在下一個三畫質共同分段邊界確認命令；結束後自動完成本次 HHC 收錄、補傳、Stop 與 seal。也可由外掛按 **停止 HHC 傳送**正常停止本次來源。

上述操作不停止 OBS 全域串流、原本本機錄影或 YouTube。Program 收錄、三畫質 NVENC、900 幀／30.03 秒分段維持不變。

前一場取得 Stop 與 seal 確認後可開始 Console 準備的下一場；前一場平台驗證仍可在背景繼續。請在 Console 與會員頁分別確認 ready、自動發布和實際播放，不以補傳歸零代表驗收完成。

## 斷線與恢復

網路失敗不等於正常結束。外掛保留原 intent、capture、命令 key 與素材，重試原操作；session 會自動更新，不改綁另一場。需要介入時按 **重新檢查／恢復補傳**。

如果 Console 撤銷本場，外掛只停止 HHC 收錄並以原 capture 執行 abort。資料保留，不自動建立替代場次。請勿在尚有輸入或待驗證場次時重設 Console 串流金鑰，否則舊 session 的恢復權限也會失效。

正常退出 OBS 後，背景補傳最長執行 24 小時，不能延長平台期限。程序異常中斷保留原 journal，不能把不完整素材當成正常完整影片。

## 舊版未完成收錄

尚未開始 K3 場次時，可按 **處理舊版未完成收錄**，使用原帳號登入恢復原 queue。此入口只處理舊 journal，不能新建舊版收錄；不會將它轉為 K3 或另建平行 capture。請先完成舊版恢復，再開始 K3。

## 移除與保留資料

關閉 OBS 後只移除外掛 DLL、背景補傳 EXE 與本外掛 data 目錄。保留設定、queue、journal 及尚未完成素材；不要刪除 OBS 原錄影。測試報告與歷史失敗證據應獨立保存。

固定契約：K3 `k3-2026-10-14.rc1`、B1 `b1-2026-10-10.rc1`、C1 `c1-2026-10-08.2`、inventory schema 1。
